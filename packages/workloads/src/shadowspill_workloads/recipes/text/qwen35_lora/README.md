# Qwen3.5 MoE checkpoint LoRA

Start with the [commented Python script](example.py):

```python
from shadowspill_workloads.recipes import LoRA, Model, train

model = Model.from_checkpoint("/checkpoints/Qwen3.5-35B-A3B", lora=LoRA())
train(model, {
    "run_dir": "runs/qwen35",
    "data": "/data/fineweb-qwen35",
    "frozen_state_id": "exact-base-checkpoint-revision",
    "sequence_length": 65536,
    "sequences_per_step": 4,
    "microbatch_sizes": [1, 2, 4],
    "chunk_sizes": [8192],
    "moe_chunk_sizes": [8192, 32768],
    "graph_pair_policies": ["cost-input", "cost-attention", "attention-input"],
    "resolution_options": ["0", "1/4", "1/2", "3/4", "1"],
    "execution_gib": 77,
    "spill_gib": 200,
})
```

The [shared runner](../../README.md) owns saved build/profile/plan/execute
phases on the local base checkpoint and tokenized corpus. It identifies the
architecture from checkpoint metadata. Computation and LoRA factors use BF16;
gradients, master weights and Adam moments use FP32. The initializer fills
Executor buffers in bounded pieces and verifies checkpoint/corpus metadata.
The recipe defaults to LoRA rank/alpha 32, 32K tokens, eight sequences per update,
28 GiB execution memory and 144 GiB pinned host spill.

`--microbatch-sizes 1 2 4 8` specifies the default candidate list explicitly.
Choose a smaller list to bound preparation work: with
`--sequences-per-step 8 --microbatch-sizes 2 4`, only sizes two and four get
training and evaluation Programs and profiles. Each size must be a positive
integer dividing the sequences per update. Repeated sizes are built once.
Changing the step size requires a matching valid list; invalid geometry fails
before workers start.

CPU planning tries all factor orderings for each built size and selects the
lowest predicted training time among jointly admitted training/evaluation Plans.
Microbatch size does not change the total update batch. The selected Plan and
input geometry are passed to `Trainer` for execution.

The default search has one unchunked cost/input graph pair; the script above
enables chunk and retention candidates explicitly. Each microbatch size is
crossed with those choices. Dense-attention retention saves backward-required
state; linear attention remains a full sequence barrier. The chunk loop is
generated by the compiler, and MoE scratch stays within its execution chunks.

Start with a fresh run directory. Later calls may pass just the same `model`,
`{"run_dir": ...}` and a named `phase`; they reuse `config.json`, including its
exact candidate list. Change memory budgets during `phase="plan"` to reuse
the saved measurements. Changing build choices requires a fresh run.
The CLI `shadowspill_workloads.recipes.text.train_qwen35_lora` uses these same workers.

# qwen35-27b_4K_8seqs

| Model | Training | Sequence length | Sequences per step | World size | Hardware |
|---|---|---|---|---|---|
| `qwen35-27b` | LoRA | 4,096 tokens | 8 (32,768 tokens) | 1 | NVIDIA GeForce RTX 5090, 32 GiB each; 188 GiB of host memory |

These define the experiment: every case of every engine shares them, and they title its figures.

LoRA fine-tuning of Qwen3.6 27B from its checkpoint on one 32 GiB GPU, its frozen base larger than the GPU: the throughput each engine reaches within the GPU memory it holds, and the host memory it needs.

Generated by `baselines/generate_experiment.py` from the `lora` template; `generation.json` records the inputs and the values derived from them. The folder is the experiment: edit it as it needs, and run it with the common runner as [the guide](../../README.md) describes.

## Scenario

| | |
|---|---|
| Model | `qwen35-27b`, its `mlops` implementation, LoRA rank 16, alpha 16.0 |
| Weights and data | `{models}/Qwen3.6-27B`, read as a Hugging Face checkpoint; the corpus `{corpora}/qwen35` |
| Geometry | 4,096-token sequences, 32,768 tokens per update, 1 GPU |
| Precision | weights bfloat16, masters none, gradients bfloat16, AdamW moments bfloat16; rounding to nearest; the narrow-gradient fusion as each engine defaults |
| Run | 1 warmup and 1 measured update per case; 8 CPU threads; at most 3600 s a case |
| Sized for | 32 GiB of GPU memory and 188 GiB of host memory; the ShadowSpill spill pool is explicitly set to 160 GiB |
| Variables | `{models}`: the directory holding the Hugging Face checkpoints, one directory per checkpoint; `{corpora}`: the directory holding the tokenized corpora prepare_corpus writes, one directory per tokenizer family |

## Engines

Each engine's options are the settings its README documents; a matrix holds the engine's own, and the shared settings above join every case.

### shadowspill: 20 cases ([options](../../../engines/shadowspill/README.md))

Every case: `spill_gib` 160.

* 20 cases: `tokens_per_microbatch` 4096, 8192, 16384, 32768; `execution_gib` 8, 12, 16, 24, 28

### fsdp2: 105 cases ([options](../../../engines/fsdp2/README.md))

Every case: `offload_policy` "cpu", `reshard_after_forward` true, `reshard_after_backward` true, `forward_prefetch` 0, `backward_prefetch` "auto".

* 90 cases: `tokens_per_microbatch` 4096, 8192, 16384; `recompute` 0, 0.25, 0.5, 0.75, 1; `activation_offload` "none", "cpu", "overlapped"; `gradient_sync` "per-microbatch", "last-microbatch"
* 15 cases: `tokens_per_microbatch` 32768; `recompute` 0, 0.25, 0.5, 0.75, 1; `activation_offload` "none", "cpu", "overlapped"

Both gradient-sync modes run for every configuration with multiple microbatches per update. With one microbatch, the modes are identical, so each configuration runs once. All cases use FSDP2's default prefetch behavior: forward `0` leaves implicit next-layer overlap in place, and backward `"auto"` uses FSDP2's automatic next-layer prefetch. Prefetch and resharding are fixed throughout the sweep. All 105 cases are distinct.

### deepspeed: 72 cases ([options](../../../engines/deepspeed/README.md))

Every case: `zero_stage` 3, `offload_param` "cpu".

* 8 cases: `tokens_per_microbatch` 4096, 8192, 16384, 32768; `recompute` 0; `offload_optimizer` "none", "cpu"
* 64 cases: `tokens_per_microbatch` 4096, 8192, 16384, 32768; `recompute` 0.25, 0.5, 0.75, 1; `offload_optimizer` "none", "cpu"; `activation_offload` "none", "cpu"

## Running it

From the repository's root, in a tmux window, first the dry run, which validates every case and launches nothing:

```bash
python -u -m baselines.experiment --spec baselines/experiments/lora_rtx5090/qwen35-27b_4K_8seqs/experiment.json \
  --variable models=<dir> --variable corpora=<dir> --dry-run
```

then the same command without `--dry-run`. A run writes everything into `output/` in this folder, which git ignores. `--engine <engine>` runs one engine and keeps what the others hold; the same command again resumes, `--retry-failed` attempts the failed cases again, and `--overwrite` runs the engines it runs from scratch. The variables' values are recorded in `output/`, so a resume need not repeat them.

## Results

A run ends with `output/summary.md` and the report in `output/report/`. To keep the summary with the experiment:

```bash
python -m baselines.summary baselines/experiments/lora_rtx5090/qwen35-27b_4K_8seqs/output \
  --publish baselines/experiments/lora_rtx5090/qwen35-27b_4K_8seqs/results
```

which writes `results/summary.md` and its figures; `python -m baselines.trace baselines/experiments/lora_rtx5090/qwen35-27b_4K_8seqs/output <engine> <case>` traces one case under Nsight Systems.

# qwen35moe-35b-a3b_32K_1seqs

| Model | Training | Sequence length | Sequences per step | World size | Hardware |
|---|---|---|---|---|---|
| `qwen35moe-35b-a3b` | LoRA | 32,768 tokens | 1 (32,768 tokens) | 1 | NVIDIA GeForce RTX 5090, 32 GiB each; 188 GiB of host memory |

These define the experiment: every case of every engine shares them, and they title its figures.

LoRA fine-tuning of Qwen3.5 35B-A3B from its checkpoint on one RTX 5090, with one 32K sequence per update and CPU parameter offload in every DeepSpeed case.

Originally generated by `baselines/generate_experiment.py` from the `lora` template; `generation.json` records the inputs and the values derived from them. The folder is the experiment: edit it as it needs, and run it with the common runner as [the guide](../../README.md) describes.

## Scenario

| | |
|---|---|
| Model | `qwen35moe-35b-a3b`, its `mlops` implementation, LoRA rank 16, alpha 16.0 |
| Weights and data | `{models}/Qwen3.5-35B-A3B`, read as a Hugging Face checkpoint; the corpus `{corpora}/qwen35` |
| Geometry | 32,768-token sequences, 32,768 tokens per update, 1 GPU |
| Precision | weights bfloat16, masters none, gradients bfloat16, AdamW moments bfloat16; rounding to nearest; the narrow-gradient fusion as each engine defaults |
| Run | 1 warmup and 1 measured update per case; 8 CPU threads; at most 3600 s a case |
| Sized for | 32 GiB of GPU memory and 188 GiB of host memory; ShadowSpill uses an explicit 160 GiB spill pool |
| Variables | `{models}`: the directory holding the Hugging Face checkpoints, one directory per checkpoint; `{corpora}`: the directory holding the tokenized corpora prepare_corpus writes, one directory per tokenizer family |

## Engines

Each engine's options are the settings its README documents; a matrix holds the engine's own, and the shared settings above join every case.

### shadowspill: 5 cases ([options](../../../engines/shadowspill/README.md))

Every case: `spill_gib` 160, `orderings` "factors".

* 5 cases: `execution_gib` 8, 12, 16, 24, 28

### deepspeed: 18 cases ([options](../../../engines/deepspeed/README.md))

Every case: `zero_stage` 3, `offload_param` "cpu".

* 2 cases: `recompute` 0; `offload_optimizer` "none", "cpu"
* 16 cases: `recompute` 0.25, 0.5, 0.75, 1; `offload_optimizer` "none", "cpu"; `activation_offload` "none", "cpu"

### fsdp2: 15 cases ([options](../../../engines/fsdp2/README.md))

Every case: `offload_policy` "cpu", `reshard_after_forward` true, `reshard_after_backward` true, `forward_prefetch` 0, `backward_prefetch` "auto", `gradient_sync` "per-microbatch".

* 15 cases: `recompute` 0, 0.25, 0.5, 0.75, 1; `activation_offload` "none", "cpu", "overlapped"

## Running it

Every case uses one 32,768-token microbatch per update. There is no gradient
accumulation, so every-microbatch and last-microbatch synchronization are the
same operation. ShadowSpill has only the 1x1 ordering at this geometry; it
still searches its recomputation/spill choices across the five GPU budgets,
with shared preparation and persistent artifacts. FSDP prefetch and resharding
are fixed; the installed single-rank CPU-offload path does not overlap weight
transfers through its prefetch controls.

The full grid includes overlapped FSDP activation offload. Two partial-recompute
overlapped cases in the preceding Qwen 27B sweep raised illegal memory accesses;
that investigation and a real-model smoke check are still outstanding. A dry
run validates configuration and local inputs, not numerical or runtime behavior.

From the repository's root, in a tmux window, first the dry run, which validates every case and launches nothing:

```bash
python -u -m baselines.experiment --spec baselines/experiments/lora_rtx5090/qwen35moe-35b-a3b_32K_1seqs/experiment.json \
  --variable models=<dir> --variable corpora=<dir> --dry-run
```

then the same command without `--dry-run`. A run writes everything into `output/` in this folder, which git ignores. `--engine <engine>` runs one engine and keeps what the others hold; the same command again resumes, `--retry-failed` attempts the failed cases again, and `--overwrite` runs the engines it runs from scratch. The variables' values are recorded in `output/`, so a resume need not repeat them.

## Results

A run ends with `output/summary.md` and the report in `output/report/`. To keep the summary with the experiment:

```bash
python -m baselines.summary baselines/experiments/lora_rtx5090/qwen35moe-35b-a3b_32K_1seqs/output \
  --publish baselines/experiments/lora_rtx5090/qwen35moe-35b-a3b_32K_1seqs/results
```

which writes `results/summary.md` and its figures; `python -m baselines.trace baselines/experiments/lora_rtx5090/qwen35moe-35b-a3b_32K_1seqs/output <engine> <case>` traces one case under Nsight Systems.
